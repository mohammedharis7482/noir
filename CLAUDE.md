# NOIR

A fictional photography portfolio designed as an exhibition catalogue: photography first, typography second, motion only where it has a purpose, interface almost invisible. A learning and showcase project, built to a production standard. The repository is public.

## Read before any work

1. `docs/DESIGN.md`: design system, every section's composition, motion vocabulary, ban list, copy and decisions. The source of truth for how things look and move.
2. `docs/BRIEF.md`: the original creative brief. Where it conflicts with `DESIGN.md`, `DESIGN.md` wins.
3. `docs/SHOTLIST.md`: the 21 photographs, their roles and file names.
4. `docs/MOTION.md`: the motion specification for every motion phase (Phase 3 onward): build order, foundation, each section's motion and how it is tested. Where it disagrees with `DESIGN.md` about motion, `MOTION.md` wins; about layout, `DESIGN.md` wins.
5. `AGENTS.md` (imported below): generated by create-next-app. Before writing Next.js code, read the relevant doc in `node_modules/next/dist/docs/` instead of relying on memory. This project is on Next.js 16.

## How we work

- One phase at a time. Never start the next phase without explicit approval.
- Start each phase with a short plan: the files you will create or change, and anything in the docs that looks unclear or contradictory. Then continue with the work, unless the prompt asks you to wait for approval.
- Stay inside the current phase's scope. If something outside it needs changing, say so and wait.
- Preserve what already works. Explain any structural change before making it.
- No new dependencies without asking first.
- Before every commit, run `npm run build` and `npm run lint`. Both must pass. (Next.js 16's build does not run the linter.)
- One branch per phase (`phase-01-foundation`, `phase-02-static`, …). Push it and open a pull request so Vercel builds a preview. If the session has to use a different branch name, say which one.
- Commit messages follow Conventional Commits: `feat:`, `fix:`, `docs:`, `chore:`, `refactor:`.
- End every phase with a report, in this order: what you found, what changed (by file), how to test it, the expected visual result, and open questions. Update the Status section, then stop.
- If a headless browser is already available in the environment, screenshot changed pages at 1440×900 and 390×844 and critique them against `DESIGN.md` before reporting. Don't add Playwright or any other tool to `package.json` for this.

## Stack

- Node 22 LTS, pinned in `.nvmrc` and in `package.json` engines. npm is the package manager.
- Next.js 16, App Router, Turbopack. TypeScript in strict mode.
- Server components by default. Add `"use client"` only to components that need motion, state or browser APIs, as low in the tree as possible.
- Tailwind CSS v4. All tokens are defined once with `@theme` in `src/app/globals.css`; there is no `tailwind.config` file.
- GSAP with ScrollTrigger, SplitText and CustomEase (all included in the `gsap` package), used through `@gsap/react` (`useGSAP`). GSAP is the only animation system: no Framer Motion, no CSS keyframes for scroll effects. Plain CSS transitions are fine for small hover and focus states.
- Lenis (package `lenis`) for wheel smoothing: one instance for the whole app, driven by `gsap.ticker` and synced to ScrollTrigger. Touch scrolling stays native.
- `next/font/google`: Instrument Serif (400, normal and italic) and Hanken Grotesk (400, 500). The cloud environment allows `fonts.googleapis.com` and `fonts.gstatic.com`. If the font download fails, report it; don't switch to another font source.
- `next/image`, used only through the `NoirImage` component. Photographs live in `public/images/plates/`; never hotlink images.
- No UI kits, icon libraries, CSS-in-JS or state libraries.

## Design non-negotiables (full list in DESIGN.md §10)

- Palette only: paper `#F4F2ED`, ink `#111111`, ink-muted `#6B6761`, rule `#D9D6D0`, white `#FFFFFF` (text over photographs). Darkroom: dark `#111111`, dark-ink `#F4F2ED`, dark-muted `#8C877F`, dark-rule `#2E2C29`. Components use semantic tokens that resolve per `data-theme`.
- Sentence case everywhere except the NOIR wordmark. Italic means "title of a work" and nothing else.
- Radius 0. No shadows, gradients, blur, cards, pills or icons.
- No eyebrow-label-plus-heading section openers. No centred image blocks except the fullscreen moment.
- Layouts come from `DESIGN.md` §6. Don't invent compositions; if one doesn't work, propose a change and wait.
- All copy comes from `DESIGN.md` §11 via `src/content/copy.ts`. Don't write new copy.
- No stock or web images as fillers. A missing photograph renders as the `NoirImage` placeholder.

## Motion rules

- Every animation ends exactly at the static layout built in Phase 2 (`MOTION.md` §0). After any animation finishes, the page matches the approved Phase 2 screenshots pixel for pixel, and the reduced-motion experience is simply the static page. A motion idea that needs a different rest layout is a layout change: propose it and wait.
- Every animation lives in a `useGSAP` hook scoped to its section's ref. No global selectors and no `document.querySelector`.
- Create `gsap.matchMedia()` inside that hook so it reverts on unmount, with three branches:
  - desktop: `(width >= 1024px) and (prefers-reduced-motion: no-preference)`
  - mobile: `(width < 1024px) and (prefers-reduced-motion: no-preference)`
  - reduced: `(prefers-reduced-motion: reduce)`. No ScrollTriggers, pins or smoothing here; content shows in its final state.
- Hover effects apply only under `(hover: hover) and (pointer: fine)`.
- Animate `transform`, `opacity` and `clip-path` only. Never width, height, top, left, margin or padding.
- Eases and durations come from `src/lib/motion.ts`. No inline magic numbers.
- SplitText: use its built-in line masking (`mask: "lines"`) with `autoSplit` and `onSplit`, so splits survive resizing and font loading.
- Call `ScrollTrigger.refresh()` once, after all sections have mounted, the fonts are ready and the hero image has loaded (`MOTION.md` §2.4).
- Each technique has assigned places (`DESIGN.md` §7). Don't reuse a technique elsewhere without asking.

## Code rules

- No `any`. Content is typed.
- Components stay under about 200 lines; split them when they grow.
- No hard-coded copy or image paths inside components; everything comes from `src/content`.
- Semantic HTML: one h1, landmarks, visible focus styles, labelled controls.
- The repository is public: never commit secrets, tokens or `.env` files.
